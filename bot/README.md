# WhatsApp bot (Laporan Kebun Cilowong)

The program behind the farm's WhatsApp number. It runs on Google Cloud Run and does two jobs:

- **Webhook** (`POST /webhook`): reads what a worker texts. A tree ID (e.g. `A1`) opens the tree Flow; `KEBUN`
  opens the farm Flow (rain and finished work). After a Flow is sent, the bot replies with a fresh Flow message,
  because WhatsApp greys out the button of a completed Flow.
- **Flow endpoint** (`POST /flow-endpoint`): answers each button in the Flows (encrypted per Meta's spec) and
  saves reports, flowering, counts, harvests, tree data, tasks and rain to Firestore.

Shared words and rules with the web app: see `docs/data-contract.md` and `src/shared/` (repository root).

**Never commit secrets here** (this repository is public): no `.env`, `env.yaml`, `.pem` private key or
service-account JSON. They stay in Cloud Run. `.gitignore` in this folder blocks them.

Two Flows, both Indonesian for the workers:

| Flow | opened by | file | env | holds |
|---|---|---|---|---|
| **Laporan Pohon** | the worker sends a tree ID, e.g. `A1` | `flows/flow.json` | `FLOW_ID` | tree info, then: Laporan Masalah, Panen & Data Pohon (bloom, counts, harvest, edit tree data) |
| **Catatan Kebun** | the "Hujan & Pekerjaan" button, or the word `KEBUN` | `flows/flow-farm.json` | `FARM_FLOW_ID` | Curah Hujan, Pekerjaan Selesai |

Anything else a worker sends (hello, a photo...) gets a friendly guide with the button.

| report | writes to (same collections the webapp reads) |
|---|---|
| Laporan Masalah (photo + words, both required; no lists) | `reports` with `triage` (what the words say), photos in Storage; tree turns Merah at once only when the words read as urgent (`conditionSource: 'triage'`) |
| (archived trees, `active: false`) | closed: the bot answers that the tree is no longer active |
| Mulai berbunga | `bloomWaves/{tree}_{date}_{part}` |
| Hitung tandan bunga / buah jadi / buah yang disisakan / buah di pohon | `cropCounts/{tree}_{season}_{stage}_{date}` (+ tree `floweringClusters` / `estimatedFruitCount`, `treeEdits`) |
| Catat panen (2 steps, grades, quality problems, photos) | `harvests/wa<hash>` |
| Ubah data pohon | `trees` + `treeEdits` |
| Pekerjaan Selesai | `seasonTasks/{block}_{season}_{task}` |
| Curah Hujan | `weather/{YYYY-MM-DD}` |

Every write has a deterministic id (token + content), so a network retry never duplicates, while a new report sent from
an old Flow message still saves. Numbers are checked on the server (`lib/rules.js`, same limits as the webapp):
hard errors are refused with a message; odd-but-possible values ask the worker to tick "Ya, sudah benar".

Tests (no real data touched): `npm test`. After editing `scripts/build-flow.js`: `npm run build-flow`.

Rule for Flow JSON: a dynamic property is always the WHOLE value (`"${data.title}"`); build any text that mixes words
and variables on the server, or it shows up literally on the phone.

## Files

| file | purpose |
|---|---|
| `index.js` | Express server: WhatsApp webhook + encrypted Flow endpoint |
| `flows/flow.json`, `flows/flow-farm.json` | The two Flows, generated by `scripts/build-flow.js` (paste each into its own Flow in WhatsApp Manager) |
| `scripts/build-flow.js` | Builds both Flow JSON files (the one place to change a screen) |
| `scripts/backfill-photos.js`, `scripts/delete-reports.js` | One-off maintenance (photo sizes; clearing test reports, `--yes` to really delete) |
| `lib/shared.js` | **Generated** from the webapp's `src/shared` (triage, health words, labels and dose): run `npm run build:bot-shared` in the repository root after changing `src/shared`; a webapp test fails if it's stale |
| `lib/rules.js` | Every range, choice, date rule, id and Indonesian message (the one place to change a rule) |
| `lib/season.js` | Where a tree is in the season (port of the webapp's guide.ts / crop.ts) |
| `lib/cropData.js` | Reads and writes bloom, counts, harvests, season tasks, rain |
| `lib/flowScreens.js` | The screens and what each button does |
| `test/` | Unit + end-to-end tests with an in-memory Firestore |
| `lib/encryption.js` | Flow request/response encryption (RSA + AES-GCM) |
| `lib/media.js` | Decrypts photos uploaded through the Flow |
| `lib/reports.js` | Saves photos to Storage, report + tree update to Firestore |
| `lib/trees.js`, `lib/firestore.js` | Firestore access |
| `seed-variants.js`, `seed-trees.js` | One-off seeding scripts |

## Firestore model

- `variants/{code}` — variety reference data
- `trees/{A1}` — one doc per tree; current `condition`, `conditionNotes`,
  `lastReportId`, `lastReportAt`, `conditionUpdatedAt`
- `treeEdits/{auto}` — audit log of measurement changes (`treeId`, `changes{field:{from,to}}`, `workerPhone`, `source`, `at`)
- `reports/{id}` — immutable history: `treeId`, `block`, `workerPhone`,
  `description`, `photos[{path,url,mimeType,size}]`, `conditionBefore`,
  `conditionAfter`, `conditionChanged`, `createdAt`

Photos live in Cloud Storage under `report-photos/{treeId}/`.

## Config (`env.yaml` for Cloud Run, `.env` locally)

See `.env.example`. Never set `PORT` on Cloud Run. `STORAGE_BUCKET` is the
bucket name shown in Firebase console → Storage.

## Deploy

```
gcloud run deploy durian-tree-lookup --source . --region asia-southeast1 --allow-unauthenticated --env-vars-file env.yaml
```

Keep one instance warm so a Flow request never waits on a cold start:

```
gcloud run services update durian-tree-lookup --region asia-southeast1 --min-instances=1
```

## Updating the bot from this repository

1. `git pull`, then go to `bot/`.
2. Copy in the three secret files from the folder you deployed from before (they are never in git):
   `env.yaml`, `service-account.json`, `private_key.pem`.
3. Deploy (same command as always, run inside `bot/`):
   `gcloud run deploy durian-tree-lookup --source . --project whatsapp-survey-509713 --region asia-southeast1 --allow-unauthenticated --env-vars-file env.yaml`

## Flow setup

A published Flow can't be edited. After changing a file in `flows/`, create a new Flow,
paste the JSON, set its endpoint URI to `<service-url>/flow-endpoint`, publish,
and put the new Flow ID in `FLOW_ID` (tree Flow) or `FARM_FLOW_ID` (farm Flow). Both Flows use the same endpoint URI.
